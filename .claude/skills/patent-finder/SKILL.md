# patent-finder

本Agentの `identity.md` を共通方針とする。パスはAgentリポジトリ基準。

1. 利用者が許可した対象、希望成果、公開状態、対象国を確認する。
2. README、構成、主要モジュール、テストを読み、解く課題と制約を短く整理する。
3. 自前のアルゴリズム、データ表現、資源制御、同期、障害回復などから候補を探す。既製部品の単純適用と独自の工夫を分ける。
4. 各候補の課題・従来手法・構成・効果をコード位置付きで示す。性能改善は測定値と予測を分ける。
5. 公開履歴の根拠を確認し、不明な日付を推測しない。未公開であることだけで特許性を判断しない。
6. 候補を根拠の強さ、未確認事項、追加調査の必要性で整理する。有望候補がない場合は理由を返す。
7. `knowledge/project-document-templates.md` の発明提案書にまとめ、対象を選んで先行技術調査へ渡す。

成果は利用者指定の保存先へ置き、根拠と未確認事項を示す。出力は専門家確認前の第一稿であり、法的判断を代替しない。
